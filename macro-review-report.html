三、分析框架优化建议

1

当前状态：收益率曲线利差散落在利率板块，Sahm Rule未计算，衰退概率模型缺失。

建议：新建独立"衰退信号"仪表盘，聚合所有衰退先行指标：

信号计算方法触发阈值历史平均领先
10Y-2Y利差已有转负12-18个月
3M-10Y利差已有数据，加计算转负10-14个月
Sahm Rule失业率3M均值-12M低点>0.5pp同步或领先1-3月
纽约联储衰退概率RECPROUSUSM156N>40%6-12个月
收益率曲线3M-10Y概率T10Y3M转负12-18个月
Conference Board LEIUSSLIND连续3月下行7个月
初请失业金4周均值已有数据突破325K2-4个月

设计为红绿灯面板：每个信号绿/黄/红三色，底部给出综合衰退概率评分（加权平均），并标注当前处于经济周期的哪个阶段（扩张早期/扩张后期/放缓/衰退/复苏）。

2

通胀分析深化模块

当前状态：CPI分项拆解做得好（能源/食品/住房/核心服务/核心商品），但缺"通胀温度计"。

建议新增：

  • 通胀分项贡献度图：用CPI分项权重×同比变化，计算各分项对总CPI的拉动贡献（气泡图或堆叠柱状图）
  • 通胀预期三重交叉：市场预期(Breakeven) + 调查预期(UMich) + 模型预期(Cleveland Fed) 三线对比，三者背离=信号
  • 核心CPI 3月/6月年化：3个月和6个月年化环比，比同比更敏感，美联储内部最看重的口径
  • 工资-通胀追踪：时薪同比 vs 核心服务CPI同比叠加，验证工资-通胀螺旋是否存在
  • 超级核心通胀(Supercore)：核心服务(除住房) — 鲍威尔最关注的口径

4

数据日历与事件追踪

当前状态：FOMC时间线已有，但缺经济数据发布日历。

建议新增：独立的"本周关键事件"面板，包括：

  • 经济数据日历：未来7天关键数据发布（CPI、非农、GDP、FOMC等），含预期值与实际值对比。可用 Treasury 或 FRED Releases API 构建
  • 国债拍卖日历：2Y/5Y/7Y/10Y/30Y拍卖日期+规模，拍卖结果影响长端利率
  • 财报季标记：标普500主要成分股财报日期——影响指数波动
  • 数据意外追踪：实际值 vs 预期值偏差，持续追踪形成"经济意外指数"
5

跨资产估值与相对价值面板

当前状态：有资产价格和相关性矩阵，但缺估值视角。

建议新增：在资产板块新增估值子模块：

  • 股权风险溢价(ERP)：标普盈利收益率(1/P/E) - 10Y实际利率(TIPS)，当前ERP处于历史什么分位
  • Fed Model：标普盈利收益率 vs 10Y名义利率，背离=股债相对吸引力
  • 铜金比趋势：铜(经济周期) / 金(避险)，比价上升=风险偏好上升
  • 油金比趋势：油(通胀) / 金(避险)，比价方向=通胀-避险博弈
  • 股债性价比打分：多因子模型给出股 vs 债配置建议（基于ERP、估值分位、利率方向）
6

信号聚合与历史胜率

当前状态：各板块有keySignals和whatToWatch，但信号之间无聚合，无历史验证。

建议新增：

  • 全局风险评分：聚合所有板块信号，输出0-100的综合风险评分（类似GS Financial Conditions Index但更透明）
  • 信号变化追踪：记录每日信号变化（新增/消失/方向反转），避免分析师淹没在数据中
  • 历史信号回测：对关键信号（如VIX>20、10Y>4.5%、Sahm触发等）做历史回测——过去触发后标普/10Y/HY的1周/1月/3月表现
  • Regime转换概率：当前regime维持/转换的概率，基于多指标综合计算
7

鹰鸽指数数据化

当前状态：FOMC官员讲话为分析师策展，鹰鸽分数为主观打分。这在专业平台上是明显的弱项——无法回溯、无法验证、无法自动化。

建议替代方案（三选一）：

方案数据源优势劣势
A. FedWatch隐含概率CME FedWatch纯市场定价，无主观偏差需爬虫或API
B. 2Y利率变化代理已有FRED数据2Y=政策预期，上升=鹰派定价不区分原因
C. NLP鹰鸽分类FOMC声明/纪要文本可回溯、可自动化需NLP模型，较复杂

推荐方案B+部分C：用2Y利率周/月变化作为"市场鹰鸽温度计"（已有数据），同时用简单的关键词频率法分析FOMC声明文本变化（"inflation"/"employment"频率、语调变化），两者交叉验证。这样鹰鸽指数从策展变为数据驱动。

8

信用市场深化

当前状态：OAS分层做得好，但违约率为硬编码3.2%，CDS缺失。

建议：

  • 违约率替换为真实数据：DRSFRMACBS 商业银行违约率(季频) 或 FRED BAMLH0A0HYM2派生计算
  • 新增CDS利差：iTraxx/CDX指数（需Bloomberg或Markit，免费源有限）→ 可用 ETF价差替代：HYG-LQD 价差追踪
  • 杠杆贷款价格：用 SRLN 或 BKLN ETF追踪杠杆贷款市场
  • CCC-IG分层利差趋势图：已有数据，建议加时间序列图（当前只在表格中）
  • 信用-股票背离追踪：HYG vs SPX 20日相关性变化，转负=信用开始领先于股票下跌

UX

UX

时间区间切换器

所有图表固定30日/90日窗口

图表上无历史关键位标注

UX

信号变化日志

每日更新但无变化记录

六、实施路线图

第一阶段
数据补缺

补充P1级数据序列（劳动力市场+衰退信号+通胀预期）

在 build_data.py 的 FRED_IDS 中新增约15个序列，在 gen_datajs.py 中新增计算逻辑（Sahm Rule、3M-10Y利差、通胀分项贡献度）。改动集中在数据层，不影响前端架构。预计新增 ~15 行FRED_ID映射 + ~60行计算逻辑。

第二阶段
框架升级

衰退概率仪表盘 + 劳动力市场子面板 + 通胀深化

在经济数据板块内重构为子Tab（增长/就业/通胀/衰退），或新增第8个导航项"衰退信号"。需要前端改动但复用现有组件（metricCardsV3、trendTable）。

第三阶段
数据质量

消除所有硬编码值，替换为真实数据驱动

违约率、信用历史分位、LPI评分、利率路径概率——全部改为从raw_series.json计算。这是从"展示平台"到"研究工具"的关键升级。

第四阶段
分析与UX

全局风险评分 + 数据日历 + 信号变化日志 + 时间区间切换

需要较多前端新组件，但分析价值最高——把平台从"数据看板"提升为"决策支持工具"。

第五阶段
进阶功能

历史信号回测 + 鹰鸽指数NLP化 + 估值面板

较重的功能，但对专业分析价值巨大。历史回测可先从简单统计开始（如"VIX突破20后标普1周表现"），NLP可用简单的词频统计开始。
